# Ouro (우로우로) — 기획서 v0

> **선순환 캘린더.** 이름은 우로보로스(자기 꼬리를 무는 뱀)의 순환에서 따왔다.
> 일정이 AI 에게 일을 넘기고, AI 의 답이 다시 일정이 된다 — 그 고리가 돌 때마다 하루가 조금씩 정리된다.
> (일본어 うろうろ「어슬렁어슬렁」과도 겹친다 — 메뉴바에 조용히 머물다 필요할 때만 움직인다.)

개발 0(기획) 산출물. 지갑지갑(Kura)의 구조·디자인을 물려받는다. 결정이 바뀌면 이 문서를 고치고 DEVLOG 에 이유를 남긴다.

---

## 1. 한 줄 정의

맥 메뉴바에 사는, **이 맥에만 저장되는** 캘린더. 정해진 시간에 **Claude·GPT 에게 일을 부탁**하고,
그 답을 다시 캘린더에 걸어 둔다. Claude 쪽에서도 MCP 로 이 캘린더를 읽고 쓴다 — **양쪽이 번갈아 움직인다.**

## 2. 초안에서 바꾼 것 (개선 7)

| # | 초안 | 바꾼 것 | 이유 |
|---|---|---|---|
| ① | 「MCP 로 연결되는 캘린더」가 곧 양방향 | **문이 둘이다.** 들어오는 문 = MCP(AI → 캘린더), 나가는 문 = **디스패처**(캘린더 → AI) | MCP 서버는 요청에 답만 한다. 스스로 대화를 시작할 수 없다(MCP `sampling` 도 «대화를 여는» 기능이 아니고 클라이언트 지원도 들쭉날쭉). 「특정 시간에 AI 에게 말 걸기」는 MCP 로는 원리상 안 된다 |
| ② | 클로드·지피티에게 「채팅 쳐주기」 | 앱 창을 조작하지 않고 **헤드리스 CLI** 로 보낸다: `claude -p` · `codex exec`. 답은 **캘린더로 돌아온다** | GUI 자동화(손쉬운 사용 API 로 입력칸에 타이핑)는 앱 업데이트 한 번에 깨지고, 잠긴 화면에선 못 돈다. CLI 는 이미 이 맥에 둘 다 있다(확인함), 구독 요금 안에서 돈다 |
| ③ | 캘린더 앱 | **앱 자체 캘린더.** 일정·부탁·답이 전부 `~/.ouro/ouro.db`(SQLite) 한 곳에. 맥 기본 캘린더(EventKit)는 v0.2 이후 **선택 기능**으로 «가져오기(읽기 전용 겹쳐 보기)» 만 | 사장 확정(개발 0). 얻는 것: 캘린더 권한 창 없음, Swift/ObjC 연동 없음, 데이터가 이 맥 밖으로 안 나감(iCloud 도 안 탐), 일정·부탁이 한 표에 있어 순환 설계가 단순. 잃는 것: 아이폰·다른 기기와 동기화 없음, 기존 일정은 가져와야 보임 |
| ④ | 「로컬이라 프라이버시 안전」 | 약속을 **정밀하게**: 일정 읽기·해석·요약은 100% 로컬. **바깥(Claude·GPT)으로 나가는 건 사용자가 쓴 부탁 문장과, 부탁에 명시적으로 붙인 일정뿐** | 「전부 로컬」 이라고 쓰면 디스패처가 그 약속을 깬다. 무엇이 나가는지 부탁마다 보여주는 게 신뢰를 만든다(Kura 의 «비번은 앱 입력칸에서만» 과 같은 결) |
| ⑤ | — | **바깥에서 들어온 글은 명령이 될 수 없다** | 자체 캘린더라 초대는 없지만 들어오는 길은 남는다: `.ics` 가져오기, 겹쳐 보기, **AI 의 답 본문**. 여기에 «이전 지시는 무시하고 …» 가 섞여 다음 부탁에 그대로 실리면 프롬프트 인젝션이다. 부탁 문장은 **사람이 쓰거나 사람이 승인한 것만**, 나머지는 언제나 «데이터» 로 따옴표 안에 담겨 간다 |
| ⑥ | AI 가 번갈아 이것저것 | AI 가 만든 부탁은 **사람이 한 번 승인해야 실행된다** + **순환 제한** | 선순환의 반대는 무한 루프다(부탁 → 답이 새 부탁을 만듦 → …). Kura 의 «AI 는 요청, 사람이 승인» 을 그대로 가져온다 |
| ⑦ | 로컬 AI 모델 탑재 | **MVP 에서 뺀다.** 자연어 입력은 규칙 파서가, 똑똑한 해석은 이미 쓰는 Claude 가 MCP 로 한다. 로컬 모델은 나중에 **사장이 필요하다고 판단할 때** 붙인다(§7) | 로컬 AI 가 맡던 일(자연어 입력·요약)은 규칙 파서 + Claude 로 대부분 덮인다. 넣으면 수 GB 다운로드·16GB 메모리 경쟁·한국어 품질 실측·엔진 설정 화면·Swift 헬퍼로 개발 2~3회가 는다. Ouro 의 해자(양방향 순환·답이 캘린더로)는 로컬 AI 와 무관하다 |

## 3. 선순환 — 한 바퀴

```
        ┌──────────── 사람 ────────────┐
        │  「내일 9시에 어제 커밋       │
        │   정리해 달라고 클로드한테」  │
        ▼                              │
  [빠른 입력] 규칙 파서 → 부탁 카드     │
        │  (시간·대상·문장·붙일 일정)   │
        ▼                              │
  [캘린더] 09:00 ◯ 부탁 ───────────────┤  보고, 고치고, 승인
        │  시간이 되면                  │
        ▼                              │
  [디스패처] claude -p "…"  (샌드박스)  │
        │                              │
        ▼                              │
  [캘린더] 09:02 ● 답 도착 ────────────┘  읽음 → 다음 일정·다음 부탁
        ▲
        │  MCP: list_events · propose_errand …
  [Claude Code / Claude 데스크톱]  ← 반대 방향에서도 고리에 들어온다
```

한 바퀴의 산출물은 언제나 **캘린더 위의 무언가**다. 그래서 채팅 기록에 묻히지 않고 «언제 무엇을 했나» 로 남는다 —
ChatGPT Tasks·Claude 예약 작업과 가장 다른 점이 이거다(그쪽 결과는 채팅방 안에 쌓인다).

## 4. 개념

| 이름 | 무엇 | 저장 |
|---|---|---|
| **일정** | 보통 캘린더 일정. 읽기·쓰기 | `~/.ouro/ouro.db` |
| **부탁** | «언제 · 누구에게(Claude/Codex) · 무엇을 · 어떤 일정을 붙여서» | `~/.ouro/ouro.db` |
| **실행** | 부탁 한 번 돈 기록 — 시작·끝·종료코드·보낸 원문·받은 답 | 같은 DB |
| **답** | 실행 결과. 캘린더에 점으로 뜨고, 펼치면 본문. 「이걸로 일정 만들기」「이어서 부탁」 | 같은 DB |

- 부탁·일정은 **반복** 가능(매일 아침 9시 브리핑 등). 반복은 표준 RRULE(RFC 5545) — 나중에 `.ics` 가져오기·내보내기가 그대로 된다.
- 일정과 부탁은 **같은 표의 두 종류**다(`kind = event | errand`). 일정 하나를 «부탁으로 바꾸기» 가 한 칸 바꾸는 일이 된다.
- 「이어서 부탁」 은 `claude -p --resume <session>` 으로 **같은 대화를 잇는다** — 어제의 답을 기억한 채 오늘 부탁이 돈다.
  이게 «순환» 의 실체다.

## 5. 기능 범위

**MVP (v0.1)**
1. 메뉴바 팝오버: 오늘/주 목록 + 작은 월 달력. 자체 DB 읽기·쓰기·수정·삭제, 알림(시작 N분 전).
2. 빠른 입력 한 줄: 「내일 3시 치과」 → 일정 카드 미리보기 → Enter.
3. 부탁 만들기·편집·즉시 실행·예약 실행(Claude Code 먼저).
4. 답을 캘린더에 표시 + 알림 센터 알림.
5. MCP: 읽기 도구 + 부탁 제안(승인 필요).

**다음 (v0.2~)**
- Codex 디스패치, 반복 부탁, 이어서 부탁
- 아침 브리핑: 오늘 일정·충돌·빈 시간(규칙으로 계산, 문장 요약이 필요하면 Claude 부탁으로)
- 일정 쓰기 MCP 도구(승인 정책은 §8)
- Claude 데스크톱용 `.mcpb` 번들(Kura 와 같은 길)
- `.ics` 내보내기·가져오기, 그리고 선택 기능으로 맥 기본 캘린더(iCloud·Google) **읽기 전용 겹쳐 보기** — 켜야만 권한을 묻는다

**안 하는 것**
- 우리 서버·계정·클라우드 동기화 — 영원히.
- GUI 자동화로 채팅앱 조작.
- 가져온 일정을 그대로 부탁으로 승격(사람이 복사해서 새로 만드는 건 된다).

## 6. 아키텍처 — Kura 대응표

```
[ Claude Code / 데스크톱 ] ──MCP stdio──▶ [ ouro-mcp (Rust 사이드카) ]
                                               │ Unix 소켓 ~/.ouro/ouro.sock
                                               ▼
[ 메뉴바 팝오버 (React) ] ◀─IPC─▶ [ Ouro.app (Tauri 2 / Rust) ]
                                   ├─ ouro.db (SQLite, rusqlite) — 일정·부탁·답 전부
                                   ├─ 스케줄러 + 디스패처 → claude -p / codex exec
                                   └─ 빠른 입력 = 규칙 파서 (로컬 엔진 자리는 비워 둠, §7)
```

| 영역 | Kura | Ouro | 비고 |
|---|---|---|---|
| 셸 | Tauri 2, 420×640 팝오버, `tray.rs` | 같음. `tray.rs` 거의 그대로 이식 | 팝오버 위치 계산·blur 숨김·재오픈 가드가 이미 다듬어져 있다 |
| 프론트 | React 19 · Tailwind 4 · framer-motion · lucide | 같음 | Pretendard 번들(외부 CDN 0)도 같게 |
| MCP | `kura-mcp` (rmcp 0.16) 사이드카 | `ouro-mcp` 같은 틀 | `externalBin`·`build-sidecars.sh`·`.mcpb` 그대로 |
| 앱↔MCP | `~/.jigap` 파일 + 하트비트 | **Unix 소켓** + 하트비트 파일 | Kura 는 «사람 승인을 몇 분 기다리는» 흐름이라 파일이 맞았다. 캘린더 읽기는 즉답이 필요한 질의라 소켓이 맞다. 승인 대기 흐름만 Kura 방식 차용 |
| 데이터 | `~/.jigap` | `~/.ouro` | 앱을 지워도 남는다(Kura 와 같은 이유) |
| 업데이트·배포 | updater + DMG + brew cask | 같음 | 개발 후반 |

**왜 Tauri 인가 (Swift 네이티브 대신)** — 솔직한 저울:
- Swift 가 유리한 것: EventKit·Foundation Models·MLX 가 모국어, `MenuBarExtra` 한 줄.
- Tauri 가 유리한 것: Kura 에서 60번 넘게 다듬은 팝오버·사이드카·서명·업데이트·배포 파이프라인과 디자인 코드를 **그대로** 가져온다. MCP 사이드카는 어차피 Rust.
- 자체 캘린더(EventKit 없음)·로컬 AI 없음으로 정하면서 **Swift 쪽 이유가 전부 빠졌다.** 결론: **Tauri, MVP 에 Swift 코드 0.** 나중에 Apple Foundation Models 를 붙이면 그때 작은 Swift 헬퍼 바이너리를 사이드카로(Kura 의 `kura-cli` 와 같은 자리).
- MCP 사이드카는 DB 를 **직접 열지 않고** 소켓으로 앱에 묻는다. 쓰는 곳이 앱 하나여야 승인·알림·팝오버 갱신이 한 길로 지나가고, SQLite 동시 쓰기 문제도 없다.
- DB 는 매일 `~/.ouro/backup/` 에 스냅숏(7일 보관) — 동기화가 없으니 이 파일이 유일한 원본이다.

## 7. 로컬 AI — MVP 에서 뺌, 자리만 남김

**결정(개발 0, 사장)**: 처음엔 로컬 모델 없이 간다. 필요해지면 사장이 정해서 넣는다.

**빠른 입력은 결정적 규칙 파서**(Rust, 한국어 상대 날짜·시간·반복 표현 + 테스트)가 전부 한다.
「내일 3시 치과」「다음 주 화요일 15시 회의」「매주 월 9시 브리핑 클로드한테」 수준이 목표다.
파서가 못 알아들으면 추측하지 않고 **칸을 비운 카드**를 보여 사람이 채운다 — 틀린 날짜로 조용히 저장되는 게 최악이다.
복잡한 문장은 Claude 에게 말하면 MCP 로 들어온다(그쪽이 로컬 모델보다 훨씬 똑똑하다).

**남겨 두는 것 (비용 ≈ 0)**
- 파서 앞에 끼울 수 있는 **엔진 자리** 하나: `trait Engine { fn parse(&self, text, now, tz) -> Draft }` — MVP 구현은 «규칙만» 하나.
- **날짜 계산은 LLM 에게 안 시킨다**는 원칙은 그대로다. 나중에 모델을 붙여도 모델은 표현만 뽑고 계산은 파서가 한다.
- **«파서가 못 알아들은 입력» 을 로컬에만 세어 둔다**(본문 저장 없이 개수·유형만). 붙일지 말지 판단할 때 이 숫자를 본다.

**나중에 붙인다면 — 후보 메모** (그때 실측)

| 순서 | 엔진 | 메모 |
|---|---|---|
| 1 | Apple Foundation Models | macOS 26+ 라 이미 조건 충족. 다운로드 0, `@Generable` 구조화 생성. 한국어 품질 실측 필요 |
| 2 | Ollama + 4B급 | 사용자가 설치·모델 선택. 16GB 에서 상주 가능 |

출처: Apple Foundation Models <https://developer.apple.com/documentation/foundationmodels>,
Ollama 구조화 출력 <https://ollama.com/blog/structured-outputs>,
MCP 명세 <https://modelcontextprotocol.io/specification>, iCalendar RRULE RFC 5545 <https://www.rfc-editor.org/rfc/rfc5545>.

## 8. MCP 도구 (초안)

| 도구 | 하는 일 | 승인 |
|---|---|---|
| `get_agenda(from, to)` | 일정 목록(로컬 날짜, 비공개 제외) — **개발 4** | 없음 |
| `find_free_time(from, to, duration_minutes, day_start, day_end)` | 빈 시간(비공개도 바쁨으로 셈, 종일은 안 막음) — **개발 4** | 없음 |
| `get_proposal(id)` | 제안 상태 — **개발 4** | 없음 |
| `list_errands` / `get_run(id)` | 부탁·답 읽기 | 없음 |
| `propose_event(...)` | 일정 제안 → 팝오버에 카드. **개발 4 로 앞당김**(개발 3, 사장 — 복잡한 자연어는 규칙 파서 대신 AI 가 맡는다) | **사람 한 번 클릭** |
| `propose_errand(...)` | 부탁 제안 | **사람 승인 + 보낼 원문 표시** |
| `update/delete_event` | v0.2 이후. 삭제는 항상 승인 | 승인 |

- **「비공개」 표시**: 일정마다 «AI 에게 숨기기» 로 두면 MCP 로 아예 안 나간다(예: 병원·가족). 개발 4 에서 일정 단위로 넣음.
- 앱이 꺼져 있으면 모든 도구가 「Ouro 앱을 켜 주세요」 로 답한다. **하트비트 파일 대신 소켓 연결 자체**가 생존 확인이다(개발 4).
- 시각은 로컬 벽시계 글자(`2026-10-02T15:00`)로 주고받고, 모든 답에 `now`(요일 포함)를 싣는다. 제안 카드는 요일을 늘 보인다.

## 9. 디스패처 — 안전 규칙

1. **실행 주체**: `claude -p "<부탁>" --output-format json` (+ `--resume`), `codex exec -s read-only --json -o <파일>`.
2. **기본 권한은 읽기 전용.** Claude 는 `--allowedTools` 를 부탁 카드에서 명시한 것만(기본 없음 = 대화만). 작업 폴더는 부탁마다 `~/.ouro/runs/<id>/`. 코드 저장소를 건드리는 부탁은 카드에서 폴더를 **사람이** 고른다.
3. **맥이 잠들어 있었다면**: 예약 시각을 놓친 부탁은 깨어날 때 «늦게 실행 / 건너뜀» 중 부탁별 설정대로. 조용히 몇 시간 늦게 돌지 않는다 — 카드에 «2시간 늦게 실행됨» 을 남긴다.
4. **순환 제한**: AI 가 만든 부탁은 승인 전엔 절대 안 돈다. 한 답에서 파생되는 부탁 깊이 ≤ 3, 하루 실행 수 상한(설정).
5. **타임아웃·중단**: 기본 10분, 팝오버에서 즉시 중단. 종료코드·stderr 를 실행 기록에 남긴다.
6. **보낸 원문을 저장한다** — «무엇이 바깥으로 나갔나» 를 사용자가 언제든 확인할 수 있게(§2-④).
